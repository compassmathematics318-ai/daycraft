# Activity library / weekly calendar redesign

Preserve the existing React/FastAPI/SQLite/CP-SAT architecture and all existing records. New definitions do not reserve time; only dated occurrences and retained explicit legacy recurrence do.

## Ownership for this change
- Backend agent: `backend/app/database.py`, `schemas.py`, `main.py`, new `calendar.py`, migrations and backend calendar API/migration tests. Preserve old API compatibility.
- Frontend agent: all `frontend/**`; library, forms, weekly grid, manual/drag/resize, App navigation and dashboard adaptation.
- Scheduling agent: `backend/app/scheduler.py`, new `backend/app/calendar_scheduler.py`, scheduler tests only; expose occurrence adapter described below. Do not edit backend main/database/schema files.
- Lead: contract, backup, integration, docs and launcher verification.
- Independent QA agent after a slot frees: `e2e/**`, review tests in new files; coordinate production fixes with owners.

## API
`GET /api/state` adds `activities: Activity[]`. Existing `classes` remains a backwards-compatible list of legacy class records. New definitions are never added to old classes.

Activity: `{id,title,category:'class'|'assessment'|'commitment',subtype:'Lecture'|'Tutorial'|'Lab'|'Personal'|'Groupwork'|null,description:'',location_id:null,building:'',room:'',course:null,start_date:null,end_date:null,assessment_start:null,assessment_end:null,legacy_class_id:null}`. Validity dates inclusive. Assessment absolute timestamps required only for assessments; subtype null for assessments. New class/commitment definitions have no schedule or duration. Server owns id and legacy_class_id. Description/context exposed as typed fields, with no claim that an LLM interprets them.

`GET /api/activities`; `POST /api/activities`; `PUT/DELETE /api/activities/{id}`. Create/update body includes definition fields, omits server-owned fields (id accepted only matching existing id for compatibility). Deletion explicitly removes linked placements with a clear UI confirmation; completed/started saved planner work is preserved as historical snapshots. Categories cannot change while placements exist unless safely validated by the backend; explain any rejection.

Occurrence: `{id,activity_id,start,end,source:'manual'|'assessment'|'legacy'}`; timestamps ISO with offset, normalized to UTC. Inputs and durations use exact five-minute precision, positive duration. Persisted occurrences have FK to definition. Metadata/location inherited from linked definition. Assessments have exactly one authoritative occurrence synchronized with assessment_start/end; their time is explicitly edited in the definition form, not copied or casually dragged.

`GET /api/calendar?week_start=YYYY-MM-DD` -> `{week_start,week_end,activities:Activity[],occurrences:Occurrence[]}`. Any input date is normalized to its containing Sunday; the response ends on Saturday, inclusive. Includes events intersecting that week in settings.timezone (America/Toronto by default), including cross-midnight events. For example, November 8–14, 2026 is one week. This display/query convention never changes persisted timestamps or legacy weekday numbering (Monday=0). `POST /api/occurrences` body `{activity_id,start,end}`; `PUT /api/occurrences/{id}` same body; `DELETE /api/occurrences/{id}`. Reject overlaps against all occurrences including legacy recurrence and assessments, invalid date bounds, invalid references, nonexistent/ambiguous naive timestamps, non-five-minute precision. Return informative 409 conflicts or 422 validation errors. Activities without location mean existing default/remote semantics.

`POST /api/calendar/copy-previous-week` body `{week_start:'YYYY-MM-DD'}` -> `{created:number,duplicates:number,skipped:[{activity_id,title,date,reason}],occurrences:Occurrence[]}`. Normalize the target date to Sunday, then copy the preceding Sunday–Saturday week. Shift class/commitment local wall times by seven calendar days in settings.timezone; respect DST, validity dates, duplicate identity+instants, all overlaps and existing target events. Never duplicate assessments. Save valid copies, report skips, repeated calls idempotent. An existing legacy recurring event already reserves target time and counts as a duplicate, not a second event.

## Legacy preservation
Retain legacy `entities/classes` raw data and /api/classes compatibility, mirrored to linked library activities with legacy_class_id. Migration imports existing records once without deleting them. Weekly reads expand original recurrence/date/exception rules into virtual occurrence IDs `legacy:{class_id}:{YYYY-MM-DD}`. Virtual occurrence edits/deletes add an exception to the old series; an edit creates a persisted individual occurrence linked to the same activity. The legacy series remains editable via the existing class editor, clearly marked Legacy weekly repeat in the library. Editing metadata synchronizes the linked legacy source; old API edits synchronize the library. No new automatic forever recurrence is created by the new forms. Prevent persisted overrides and expanded legacy events from appearing twice.

Backend helper public interface: `calendar.occurrences_between(db,start_date,end_date,settings)->list[dict]` returns intersecting unified occurrences. `calendar.activities_list(db)->list[dict]` returns definitions. `calendar.sync_legacy(db,settings)` creates/updates missing mirrors and is idempotent (needed for old API writes and demo). Backend owns these functions and API mounting.

## Scheduler integration
Scheduling agent exports `calendar_scheduler.fixed_blocks_for_day(date,settings,activities,occurrences)->list[dict]`. Join definition metadata, retain occurrence_id/activity_id/category/subtype/description/course/building/room, set kind='class', locked=true, class_id='occurrence:'+occurrence.id, actual timezone-aware start/end and resolved location. Clip cross-day intervals to selected day only while retaining actual bounds metadata; report waking/sleep conflicts rather than ignoring the occupied time. Keep historical completed/in_progress blocks, but rebuild all other fixed calendar blocks from authoritative source on regeneration. Backend generation calls unified occurrences for selected date, passes legacy `classes=[]` to generate_schedule, and appends adapter fixed blocks to preserved work. Thus neither legacy nor newly persisted occurrences is duplicated or disconnected. Typed planner Block gains optional metadata fields. Route preparation includes activity locations. Upcoming assessments remain accessible in /state and calendar for deadline context; do not claim automatic inferred study work from descriptions.

Frontend dashboard obtains dated occurrences for selected Sunday–Saturday week/day and joins activities for occupied-time/upcoming previews, while existing tasks/projects/planner/maps/themes remain working. Library forms use existing timezone conversion utilities. Seven-day grid Sunday first, full day scroll, five-minute snap, 60-minute first drop, clear drag previews, move/resize persistence, explicit manual Schedule alternative. A compact searchable palette beside the grid references the same saved class/commitment definitions and occurrence endpoints as the library; it has no separate scheduling state. Assessments remain absent from the reusable palette and are changed only through their explicit editor.
